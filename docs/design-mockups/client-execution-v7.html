DIFF · 两案差异与共同点

方案 A · 段落粒度 合并行数 = 执行段数（多轮多行）；
中间叙述文本平铺可见（工作叙事外露，用户不展开也知道 agent 每步在说什么）；
每行用时 = 该段耗时；适合长过程、多轮的任务型 agent。
方案 B · 消息级粒度 合并行数 = 恒为 1 行（最简）；
中间叙述文本收进展开区（收起时消息流只有一行摘要 + 最终回答）；
摘要 = 全消息汇总；适合轻量助手——过程对终端用户是黑盒，感兴趣才点开。
共同点：合并行文案统一「✓ 已完成 · 执行了 x 个工具 · 用时」；执行中形态同为「● 执行中 · 当前命令实时可见」；点击行展开执行细节（思考折叠 + 每步工具 + 耗时）；并行多工具合并「执行了 x 个命令」不变。
